# AstrBot SystemOne 智能自动回复插件

[![AstrBot](https://img.shields.io/badge/AstrBot-Plugin-blue.svg)](https://github.com/AstrBotDevs/AstrBot)
[![TypeSafe](https://img.shields.io/badge/TypeSafe-Jev%20System%20One-brightgreen.svg)](https://typesafe.ai)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

> **让机器人按你写好的标准答案回答，该答的答、不该答的不答。**

本插件只做三件事：**本地正则召回 → Jev 判定是否真提问 → 回复标准答案**。

它不靠关键词堆砌，也不让大模型自由发挥。你先维护一张**固定问答表**，每条问答对由「问题 Q + 答案 A」组成；消息进来后先用 Q 做本地正则召回（零 API 开销），只有命中了才把 Q 与 A 一起交给 TypeSafe AI（Jev System One）判断这条消息**是不是真的在问这件事**——借此过滤掉「只是字面上包含了关键词」的假命中，最后把 A 作为唯一事实来源给出回复。

## 核心特性

### 📚 固定问答表驱动

- **本地正则召回**：Q 支持 KeyReply 风格的 `%` 通配符。未命中直接静默，**不调用 Jev、不调用 LLM**，零成本。
- **Jev 相关性判定**：命中后把 Q、答案 A 与「附加判定增强」一起交给 Jev 做二分类判断——**真提问**还是**假命中**。
  - 例：Q = `金锭`，消息「我买了个金锭形状的钥匙扣」→ 判为假命中，静默。
  - 例：Q = `金锭`，消息「金锭怎么做」→ 判为真提问，回复。
- **答案 A 是唯一事实来源**：LLM 只做措辞润色与上下文衔接，不得新增、修改或推测任何事实内容；生成失败时自动回退为原样发送 A。
- **附加判定增强（hint）**：每条答案可附一段只给 Jev 看的语境说明（不会发给用户），用于区分容易混淆的情况。

### 🔀 判定粒度可按条目控制

每条问答对右侧有独立的 **Jev 判定开关**（默认开启）：

| 状态 | 行为 | 适用场景 |
|---|---|---|
| **✓ Jev 判定** | 命中后交给 Jev 判断，真提问才回复 | 容易被字面命中的话题 |
| **○ 直接回复** | 命中即发送固定答案，不调用 Jev 也不调用 LLM | 服务器 IP、群规这类确定性问答 |

同一条消息命中多个条目时，**未开启判定的条目优先直接回复**。

### 🗂️ 答案为中心的组织方式

- **一个答案只写一次**，可以在它下面挂多个问法（多 Q 一 A）。例：`金锭` / `金锭怎么获得` / `金锭怎么做` 共用同一份答案与说明。
- **每个群、每个私聊可拥有独立问答表**；未单独配置的会话回退到全局默认表。
- **一张表可同时服务多个群**（多群一域），便于按群组分批管理。
- **一键复制 KeyReply 问答表**：自动探测 KeyReply 的 `triggers.yml` 并复制到本插件自己的数据目录，之后不再依赖对方。

### 🖼️ 图片答案

- 答案可以只有图片，也可以图文并存。
- 折叠态显示极小缩略图；图片加载失败时自动退化为可点击的链接文字，不留破图。

### 🛡️ 多级防乱插话机制

- 会话级与用户级独立冷却时间（Cooldown）。
- 最大连续主动回复次数限制（避免机器人自言自语刷屏）。
- 黑白名单（会话/用户，黑名单 > 白名单，支持多候选 ID 匹配不同适配器）。
- 消息长度、纯表情/图片过滤、指令过滤。
- 内置每分钟滑动窗口限流与可选轻量内存缓存。

### 🎨 回复定制

- 9 种回复风格：自然、简洁、专业、友好、幽默、活泼、严谨、群友、自定义。
- 5 档回复长度：极短、简短、正常、详细、自然/精炼，另有最大字数硬保护。
- 可配置的思考与打字延时（随机区间或固定秒数），避免秒回显得机械。

### 🛡️ 故障隔离

TypeSafe 超时、限流（429）、鉴权失败或网络异常时按配置降级（默认静默），并且**判定失败一律判为「不相关」**——宁可静默，也不猜测性回复错误答案。绝不影响 AstrBot 消息管道。

## 工作流程图

```text
              ┌──────────────┐
              │  用户消息     │
              └──────┬───────┘
                     ↓
              ┌────────────────┐
              │ 本地过滤        │ 黑白名单 / 长度 / 纯媒体 / 冷却 / 连续回复上限
              └──────┬─────────┘
                     ↓
              ┌────────────────┐
              │ ① 正则召回 Q   │ 本地执行，零 API 开销
              │  命中了吗？     │
              └──────┬─────────┘
                 否  │  是
          ┌──────────┘  └────────────┐
          ↓                          ↓
      ┌────────┐         ┌───────────────────┐
      │  静默   │         │ ② Jev 相关性判定  │ 把 Q + A + 附加说明交给 Jev
      └────────┘         │  真提问 / 假命中？ │
                         └─────────┬─────────┘
                            假命中 │ 真提问
                     ┌─────────────┘ └──────────┐
                     ↓                          ↓
                 ┌────────┐         ┌──────────────────┐
                 │  静默   │         │ ③ 回复答案 A      │ LLM 围绕 A 生成
                 └────────┘         │                  │ 或原样发送（按条目设置）
                                    └──────────────────┘
```

> 注：标了「直接回复」的问答对会跳过 ②，命中 ① 后直接进入 ③ 并原样发送 A。

## 安装说明

### 方式一：AstrBot WebUI 插件市场安装
在 AstrBot 控制面板中的“插件市场”搜索 `astrbot_plugin_systemone_keyreply` 并点击安装。

### 方式二：手动安装
进入 AstrBot 的 `data/plugins/` 目录，克隆或解压本项目：
```bash
cd data/plugins/
git clone https://github.com/mmyddd/astrbot_plugin_systemone_keyreply.git
```
在 AstrBot 对应 Python 环境中安装依赖：
```bash
pip install -r astrbot_plugin_systemone_keyreply/requirements.txt
```
重启 AstrBot 即可。本插件仅依赖 `typesafe-sdk`。

### 从旧版本升级（`astrbot_plugin_typesafe_keyreply` → `astrbot_plugin_systemone_keyreply`）

本版本把插件名、页面与配置键统一到 SystemOne 命名。**配置不用重填，数据不用手搬**：

| 变更项 | 旧 | 新 | 需要你做什么 |
|---|---|---|---|
| 插件名 | `astrbot_plugin_typesafe_keyreply` | `astrbot_plugin_systemone_keyreply` | 按新插件名重新安装/克隆 |
| 配置键 | `typesafe_api_key` 等 5 项 | `systemone_api_key` 等 5 项 | 无，启动时自动迁移并保存 |
| 数据目录 | `plugin_data/astrbot_plugin_typesafe_keyreply/` | `plugin_data/astrbot_plugin_systemone_keyreply/` | 无，首次启动自动复制（不覆盖已有数据） |
| 插件页 id | `typesafe-console` | `systemone-console` | 无 |
| 指令 | `/typesafe_status`、`/typesafe_test` | `/systemone_status`、`/systemone_test` | 改用新指令名（未保留旧别名） |

> [!NOTE]
> **术语**：SystemOne 是 TypeSafe 提出的大模型规范（接口路径 `/v1/systemone`，模型 Jev System One），
> 不是品牌；厂商、SDK、控制台与官方域名仍写作 TypeSafe。

## 快速上手

### 第一步：填写 API Key

进入 **插件 -> SystemOne 智能自动回复 -> 配置中心 -> SystemOne 判定**，填入 API 密钥（形如 `sk_...`），保存后在「运行状态」页点一次**测试 SystemOne 连通性**确认可用。

如果你通过自建反代或网关访问 TypeSafe，可以顺手填写 **SystemOne API Base URL**。**该地址只需填到域名（或反代根路径），插件会自动在其后追加 `/v1/systemone` 后缀**——所以不要自己把 `/v1/systemone` 写进去。留空则使用官方地址 `https://api.typesafe.ai`。漏写 `https://` 或误带后缀都会被自动纠正。

### 第二步：维护问答表

进入 **固定问答** 标签页。每个「答案」卡片代表一条标准答案，你只需要：

1. 填写**答案 A**（会被作为唯一事实来源）；
2. 可选填写 **Jev 判定辅助说明**（例如「该回答适合用户询问金锭怎么做的语境」）；
3. 在下方**逐个添加问法 Q**，支持 `%` 通配符；
4. 按需用每条问答对右侧的开关控制是否交给 Jev 判定。

如果你已经在用 KeyReply，可以直接点右上角 **「一键复制 KeyReply 问答表」** 把现有数据搬过来。

### 第三步：调整风格与频控

在「配置中心」里按群聊氛围调整回复风格、长度与冷却时间。

## 配置中心

在 AstrBot Web 控制台进入 **插件 -> SystemOne 智能自动回复 -> 配置中心**。页面分四个标签页：

| 标签页 | 用途 |
|---|---|
| **配置中心** | 按 9 个分组编辑全部 39 项配置，支持单项/整组恢复默认、改动高亮与一键保存热重载 |
| **固定问答** | 维护问答表：答案为中心的分组卡片、多问法、Jev 判定开关、KeyReply 一键复制、命中测试 |
| **运行状态** | 等价于 `/systemone_status` 的结构化面板，含限流用量条、问答表规模与**一键连通性测试** |
| **在线试判** | 输入一条消息真实跑一遍「正则召回 → Jev 相关性判定」，展示召回条目、判定结论、置信度与理由 |

页面能力要点：

- **API Key 掩码**：读取时返回 `sk_a********lmno` 形式的掩码，保持掩码提交即表示不修改，密钥不会被 `********` 覆盖。
- **保存即热重载**：保存后自动调用 `save_config()` 并尝试重载插件，无需重启 AstrBot；重载不可用时会在页面提示。
- **与原生表单共存**：若你的 AstrBot 版本不支持插件页，后端会打印一条警告并跳过路由注册，插件主体功能不受影响，仍可用原生表单配置。

### 配置分组一览

| 分组 | 内容 |
|---|---|
| 基础开关 | 插件总开关、群聊/私聊启用、忽略机器人消息/指令/纯媒体、上下文条数 |
| SystemOne 判定 | API Key、API Base URL（自动追加 `/v1/systemone`）、判定模型（支持自定义）、超时、失败处理策略、限流与缓存 |
| 回复生成 | 模型来源（跟随会话/指定 Provider）、回复风格、长度模式、字数上限、附加提示词 |
| 固定问答表（KeyReply） | 相关性判定最低置信度 |
| 模拟真人延时 | 延时开关、随机/固定模式与区间 |
| 防刷屏与频控 | 会话冷却、用户冷却、最大连续回复次数 |
| 黑白名单 | 生效模式与四张名单（会话/用户 × 白/黑） |
| 消息卫生过滤 | 最短/最长检测长度 |
| 调试 | 调试日志开关 |

## 建议与最佳实践

> [!TIP]
> 1. **关于 AstrBot 原生主动回复**：使用本插件时，建议在 AstrBot 会话设置中关闭原生随机主动回复，避免两套机制叠加触发。
> 2. **活跃群聊防刷屏**：对于发言非常频繁的群聊，建议适当调大「同一会话回复冷却」（如 60 秒）。
> 3. **通配符要写准**：`%` 代表任意内容。Q 写 `金锭%` 能命中「金锭怎么做」，但若写成 `金%`，则「今天金价」也会被召回——虽然 Jev 会判为假命中而静默，但仍会消耗一次判定额度。
> 4. **善用附加判定增强**：当某个词容易被误命中时，在答案下补一句语境说明（如「该回答适合用户询问金锭怎么做的语境」），Jev 的判断会明显更准。
> 5. **确定性问答关掉判定**：像「服务器 IP」这种不需要区分的问答对，设为「直接回复」可完全省掉 Jev 调用。
> 6. **自建反代填 Base URL**：只填到域名即可，`/v1/systemone` 由插件自动追加；填错时可在「运行状态」页对照 **API 地址** 一行确认实际生效值。
